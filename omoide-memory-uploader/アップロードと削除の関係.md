# アップロードと削除の関係

## 概要

アップロード（`GdriveUploadWorker`）と削除（`GdriveDeleteWorker`）は**完全に独立した手動操作**であり、
どちらか一方がもう一方のデータを自動的に巻き込むことはない。

---

## UploadState の状態遷移

```mermaid
stateDiagram-v2
    direction LR
    [*] --> UPLOAD_TRIGGERED : ユーザーがアップロード対象を選択して実行（triggered）
    UPLOAD_TRIGGERED --> DONE : アップロード成功（done）
    UPLOAD_TRIGGERED --> UPLOAD_TRIGGERED : Drive 容量不足で中断\n（残ファイルは待機）
    DONE --> DELETED : サーバーが取り込み済みマーク後に Drive から削除

    note right of DELETED
        削除によって Drive 容量が解放され
        UPLOAD_TRIGGERED の残ファイルを
        再開できるようになる
    end note
```

## アップロードの挙動（GdriveUploadWorker）

```mermaid
flowchart TD
    A([ユーザーがファイルを選択して実行]) --> B[UPLOAD_TRIGGERED に更新]
    B --> C[GdriveUploadWorker 起動\nUPLOAD_TRIGGERED を全件取得]
    C --> D{1件ずつアップロード}

    D --> E[アップロード成功]
    E --> F[successResults に追加]
    F --> D

    D --> G[Drive 容量オーバーで失敗]
    G --> H[成功分のみ DONE に更新\n※ 失敗・未着手は UPLOAD_TRIGGERED のまま放置]
    H --> J[Worker を失敗終了]

    D --> K[全件成功]
    K --> L[全件 DONE に更新]
    L --> M([完了])

    J --> N([UploadTriggeredSelectionScreen\nで残件数を確認])
    N --> O([Drive 側の空き容量を確保])
    O --> P([「再実行」ボタンをタップ])
    P --> C
```

> **Drive 容量を空けてから再実行ボタンを押すだけでよい。**
> ローカルの `UPLOAD_TRIGGERED` レコードが残っている限り何度でも再試行できる。

---

## 削除の挙動（GdriveDeleteWorker）

```mermaid
flowchart TD
    A([ユーザーが FileSelectionScreen で\nチェックボックスで削除対象を選択]) --> B[GdriveDeleteWorker 起動\n選択した ID のみ対象として受け取る]
    B --> C{Drive 上の各ファイルを確認}

    C --> E{ダウンローダーが受け取り済み？\ndownloaded プロパティ確認}
    E -- 受け取り済み --> F[Drive から削除]
    F --> G[deleted に追加]
    E -- 未受け取り --> H[スキップ\nログ出力のみ]

    C --> I[Drive 上に存在しない]
    I --> J[削除成功扱い\nべき等性の確保]

    G --> K([削除完了])
    H --> K
    J --> K
```

`UPLOAD_TRIGGERED` 状態のファイルを自動的にスキャンして削除することはない。

> **アップロードしたがまだダウンローダー側で受け取られていないファイルは削除されない。**

## 容量オーバー時の推奨運用手順

```mermaid
sequenceDiagram
    actor User
    participant Screen as UploadTriggeredSelectionScreen
    participant UW as GdriveUploadWorker
    participant Drive as Google Drive
    participant DW as GdriveDeleteWorker

    User->>Screen: ファイルを選択してアップロード実行
    Screen->>UW: アップロード Worker を起動
    UW->>Drive: ファイルを順番にアップロード
    Drive-->>UW: 途中で容量オーバーエラー
    UW->>UW: 成功分のみ DONE に更新<br>残りは UPLOAD_TRIGGERED のまま
    UW-->>Screen: 失敗通知

    User->>Screen: 残件数を確認
    User->>Screen: 不要ファイルを選択して削除依頼
    Screen->>DW: 削除 Worker を起動（選択 ID のみ）
    DW->>Drive: ダウンローダーが受け取り済みのファイルのみ削除
    Drive-->>DW: 削除完了

    User->>Screen: 「再実行」ボタンをタップ
    Screen->>UW: アップロード Worker を再起動
    UW->>Drive: UPLOAD_TRIGGERED を再スキャンして再アップロード
    Drive-->>UW: アップロード成功
    UW->>UW: 全件 DONE に更新
    UW-->>Screen: 完了
```

## まとめ：アップロードと削除が干渉しない理由

```mermaid
flowchart LR
    subgraph 懸念["⚠️ 懸念点"]
        C1["削除 Worker が\nUPLOAD_TRIGGERED を自動削除?"]
        C2["容量オーバー時に\nローカルから消える?"]
        C3["未ダウンロードファイルが\n削除される?"]
    end

    subgraph 保護["✅ 設計上の保護"]
        P1["削除はユーザーが選択した ID のみ対象\n自動スキャンなし"]
        P2["失敗時は何も変更しない\nUPLOAD_TRIGGERED のまま残存\n→ 次回再実行で拾われる"]
        P3["ダウンローダーが受け取り済みか確認\n（downloaded プロパティ）がガードになっている"]
    end

    C1 --> P1
    C2 --> P2
    C3 --> P3
```
